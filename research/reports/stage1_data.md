## Единая таблица `trades` (view в `data/polymarket.duckdb`)
`ts, wallet, market_id, outcome, outcome_idx, side, price, size_usd, tx_hash, block, log_index, role, source, yes_price, yes_qty`

- Каждый fill даёт две строки: maker и taker. `taker_direction` всегда противоположен `maker_direction` (проверено).
- `yes_qty` — знаковое количество в YES-эквиваленте: покупка NO ≡ продажа YES. Нужно для расчёта позиций и PnL без двусмысленности mint/merge-матчей.
- Это view, а не копия: материализация удвоила бы объём.

## Проверки (`ingest/validate.py`)
- Σ `yes_qty` по всем HF-сторонам = 0.000: сделки симметричны;
- 0 цен вне (0, 1), 0 пустых кошельков и исходов;
- Σ fills / Gamma-volume ≈ 0.5 (медиана) для sports, esports, weather и crypto. Gamma считает объём обеих сторон, так что это ожидаемое значение. Для politics и tech ≈ 0.3: часть объёма — конвертации и мерджи neg-risk, которые не являются сделками CLOB.

## Ограничения и решения, которые нужно помнить
1. **`tx_hash` для HF-данных не хранится** (55% размера файла, на диск бы не влезло). Однозначный ключ — `(block, log_index)`; хэш можно добрать точечно для сигналов. В API-данных `tx_hash` есть.
2. **Смещение отбора в конце периода**: в вселенной только рынки, закрытые до 2026-10-04. В августе–сентябре 2026 видны лишь рынки, которые резолвятся быстро (кошельков за месяц 160–190k против 450–540k весной). В бэктесте окно OOS должно заканчиваться заметно раньше конца данных, а допуск рынка нужно определять по информации на момент сигнала: запланированная дата конца и объём на эту дату. Финальный объём использовать нельзя.
3. Фильтр «объём ≥ $10k» в скоринге кошельков использует финальный объём рынка. Это мягкий look-ahead; в Этапе 2 перейду на объём на дату.
4. Комиссии в `trades.parquet` не включены. В бэктесте это будет настраиваемый fee (bps), по умолчанию с учётом taker-комиссий 2026 года.
5. Data API v1 закрыт. В v2 пагинация только курсорная, поэтому ограничения 10k offset больше нет. Фильтр по времени API игнорирует: листаю курсором от новых сделок к старым до даты отсечки.
6. HF ограничивает анонимные запросы к `resolve` (3000 за 5 мин). Чтение идёт через подписанный CDN-URL.
